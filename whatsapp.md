# WhatsApp Integration Architecture & Rules (`whatsapp.md`)

This document defines the complete architecture, engineering standards, safety rules, and implementation blueprints for the **100% Free WhatsApp Integration** in Rithu Snacks using the admin's personal WhatsApp number.

---

## 1. Overview & Core Objectives

1. **100% Free Forever:**
   - Zero third-party API subscription fees (No Twilio, No Gallabox, No Wati).
   - Zero Meta Cloud API per-conversation charges.
   - Built on top of `@whiskeysockets/baileys` (an open-source, lightweight WebSocket reimplementation of the WhatsApp Web binary protocol).
2. **Admin's Own Number:**
   - Authenticated via the phone's native **"Linked Devices"** QR code scan.
   - All customer communications appear directly from the admin's trusted business phone number.
3. **Admin Dashboard Placement:**
   - Accessible via the Admin Sidebar under the **ADMINISTRATION** group, placed **directly above Settings**.
   - Dedicated management hub at `/admin/dashboard/whatsapp`.

## 3. Strict Rules & Anti-Ban Safeguards

### Rule 1: History & Chat Sync Must Be Disabled
* **Never** sync chat history or full app state. By default, Baileys attempts to download personal chat backups, which consumes 300MB+ RAM and fills the server disk.
* **Mandatory Socket Configuration:**
  ```ts
  syncFullHistory: false,           // ⚡ Critical: Prevents downloading old chats
  markOnlineOnConnect: false,       // Keeps phone from broadcasting "Online" 24/7
  printQRInTerminal: false,         // Display QR inside Admin UI, not terminal logs
  logger: pino({ level: 'silent' }) // Suppress binary packet dumps
  ```

### Rule 2: Next.js Singleton Lock (Hot-Reload Protection)
* Next.js App Router and development server re-evaluate files upon save (HMR). Opening multiple simultaneous sockets to WhatsApp will **immediately flag and disconnect the phone number**.
* **Mandatory Pattern:** Bind the client to `globalThis` with a connection mutex so only **one persistent socket** runs across the entire Node process.

### Rule 3: Anti-Ban Rate-Limiting & Jitter Queue
* Never dispatch multiple WhatsApp messages simultaneously in a tight loop.
* **Mandatory Dispatch Rules:**
  1. Messages must be enqueued and dispatched sequentially.
  2. Simulate human presence by sending `sock.sendPresenceUpdate('composing', jid)` before dispatching.
  3. Enforce a **1,500ms – 2,500ms random delay (jitter)** between successive messages.
  4. Only transactional messages (Order Confirmation, Dispatch, Delivery, Invoice) should be sent. Never blast unsolicited bulk marketing spam.

### Rule 4: Credential Security & Git Hygiene
* Authentication keys generated by `useMultiFileAuthState('./auth_baileys')` hold raw cryptographic keys tied to the admin's phone.
* **`auth_baileys/` MUST be added to `.gitignore`**. Under no circumstances should authentication keys be committed to version control.

### Rule 5: Phone Number Sanitization (Indian Format)
* Indian phone numbers must always be normalized to WhatsApp JID format (`<countrycode><number>@s.whatsapp.net`).
* Leading zeros (`0`), country code prefixes (`+91`, `91`), whitespace, parentheses, and dashes must be cleanly stripped and formatted:
  ```ts
  export function formatToWhatsAppJid(phone: string): string {
    let cleaned = phone.replace(/\D/g, '');
    if (cleaned.startsWith('0')) cleaned = cleaned.substring(1);
    if (cleaned.length === 10) cleaned = '91' + cleaned;
    return `${cleaned}@s.whatsapp.net`;
  }
  ```

1. **Connection Status & Pairing Card:**

   * **🟡 Pairing (Scan QR):** Renders high-contrast QR code generated from pairing string, with a 4-step guide:

     2. Tap **Settings** (iOS) or **Three Dots** (Android).
     3. Select **Linked Devices** > **Link a Device**.
     4. Point your camera at the screen to scan.
   * **🟢 Connected:** Displays green active indicator, linked admin phone number (e.g., `+91 98765 43210`), session uptime, and a "Disconnect / Logout" button.

2. **Quick Message & Testing Tool:**
   * Recipient phone number input with `+91` auto-prefix.
   * Template selector dropdown:
     * *Order Confirmed*
     * *Out for Delivery*
     * *Order Delivered*
     * *Custom Message*
   * Text area with character count and dynamic variables (`{customer_name}`, `{order_id}`, `{amount}`).
   * "Send Message" button with pending spinner and delivery notification toast.

3. **Session Logs / Activity Feed:**
   * Shows recent outgoing messages with timestamp, recipient, and status (Sent / Failed).

## 8. WhatsApp Campaign Management System (200–500 Customers)

### 8.1 Safe Bulk Messaging Philosophy
To prevent WhatsApp number bans while retaining **100% free delivery** directly from the admin's personal number, campaigns strictly adhere to:
1. **Audience Limitation:** Best suited for **200 to 500 customers** per campaign batch.
2. **Zero Simultaneous Blasting:** Messages are **NEVER sent in parallel**. Every recipient is queued and processed strictly **1-by-1**.
3. **Randomized Human Typing Jitter:** Before sending each message, the engine transmits a WhatsApp `composing` state to simulate real human typing with a randomized delay of **2,500ms to 4,500ms** between contacts.
4. **Disconnect Circuit Breaker:** If the admin phone loses battery, network, or disconnects, the campaign automatically switches to `PAUSED` instead of failing recipients. Resuming is 1-click once the phone reconnects.
5. **Background Scheduling:** If scheduled for a specific time (e.g. 12:00 PM), the background scheduler wakes up automatically, changes status from `SCHEDULED` to `RUNNING`, and starts delivering without requiring any browser tab to stay open.

### 8.2 Database Architecture (Prisma & MariaDB)
- **`whatsapp_campaigns` (`WhatsAppCampaign`):** Stores campaign title, type (`FESTIVAL`, `OFFER`, `PROMOTION`, `CUSTOM`), status (`DRAFT`, `SCHEDULED`, `RUNNING`, `PAUSED`, `COMPLETED`, `CANCELLED`), message body, banner image URL, counters, and scheduling timestamps.
- **`whatsapp_campaign_recipients` (`WhatsAppCampaignRecipient`):** Individual recipient tracking with unique compound index `[campaign_id, phone_number]`. Tracks status (`QUEUED`, `SENDING`, `SENT`, `FAILED`, `SKIPPED`), message ID returned by WhatsApp servers, error logs, and delivery timestamps.
- **`whatsapp_templates` (`WhatsAppTemplate`):** Pre-seeded with festive presets (Diwali, Pongal, Weekend Flash Sale, New Launch) and supports user-created custom templates with dynamic tags (`{{customer_name}}`, `{{store_name}}`).

### 8.3 Admin Navigation & Modules
- **Overview (`/admin/dashboard/whatsapp`):** Device QR pairing, live socket state, and single-recipient transactional message tester.
- **Campaigns (`/admin/dashboard/whatsapp/campaigns`):** Campaign dashboard with live animated progress bars (polling every 3s during active runs), status filters, and action controls (Pause, Resume, Cancel, Retry Failed, Delete).
- **Create Campaign Wizard (`/admin/dashboard/whatsapp/campaigns/create`):**
  - Step 1: Campaign details & category.
  - Step 2: Customer audience selection from real database with filter pills (WhatsApp Ready, Recent Buyers, Customers with Orders, All), search, and >500 count warning banner.
  - Step 3: Message & media composer with dynamic variable insertion (`{{customer_name}}`, `{{store_name}}`), image attachment, and live WhatsApp chat bubble mockup preview.
  - Step 4: Schedule (Send Now vs Schedule Date/Time) with anti-ban summary and estimated execution time (~3.5s per recipient).
- **Templates (`/admin/dashboard/whatsapp/templates`):** Festive & promotional template catalog with "Use in Campaign" 1-click routing and custom template creation modal.
- **Reports & Analytics (`/admin/dashboard/whatsapp/reports`):** Overall delivery rate percentage, total messages sent, campaign performance table, and full per-recipient audit modal with error logs and delivery timestamps.
